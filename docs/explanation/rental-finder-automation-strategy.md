# 租屋自動化技術策略說明

解釋台北租屋自動化系統的技術選型理由與設計思維。

---

## 為什麼需要自動化？

### 問題

- **時間成本高**：每天 1-2 小時瀏覽 Facebook 社團和 591
- **資訊碎片化**：好房源分散在 18+ 個社團
- **稍縱即逝**：熱門房源數小時內被租走
- **篩選困難**：需人工檢查詳細條件

### 效益

- ⏱️ 時間節省：每天 2 小時 → 10 分鐘
- 🎯 資訊覆蓋：3-5 個社團 → 18 個社團
- ⚡ 即時性：每天 2-3 次 → 每小時自動檢查
- 🔍 精準度：自動化深度條件過濾

## 為什麼 Facebook 優先？

### Facebook vs 591

| 項目         | Facebook 社團  | 591 租屋網    |
| ------------ | -------------- | ------------- |
| **房源類型** | 房東自租為主   | 房仲+房東     |
| **更新頻率** | 即時（分鐘級） | 每日更新      |
| **互動成本** | 直接私訊房東   | 需透過平台    |
| **反爬蟲**   | 中等（需登入） | 強（IP 封鎖） |

### Facebook 優勢

1. **房東直租**：跳過仲介，節省仲介費（通常 1 個月租金）
2. **即時性**：房東發文後立即可見，搶得先機
3. **真實性**：社群監督，詐騙率較低
4. **彈性溝通**：直接與房東協商

### 591 定位

作為輔助資料來源：

- 結構化搜尋（地區、價格、坪數）
- 覆蓋不使用 Facebook 的房東
- 專業房源資訊（格局、樓層、設備）

## 為什麼用 Chrome DevTools MCP？

### 優勢

**1. 完全自動化**

- 一鍵完成：登入 → 搜尋 → 爬取 → 儲存

**2. 模擬真實用戶**

- 使用真實瀏覽器環境
- Cookie、LocalStorage 持久化
- 隨機延遲、滾動行為

**3. 處理動態內容**

- Facebook 是 React SPA
- 內容動態載入（Infinite Scroll）

**4. 避免封鎖**

- 不被識別為爬蟲
- 可通過 CAPTCHA（手動介入）

## 為什麼用 Telegram？

### LINE Notify vs Telegram

| 項目         | LINE Notify           | Telegram Bot     |
| ------------ | --------------------- | ---------------- |
| **服務狀態** | ❌ 2025/3/31 停止服務 | ✅ 持續運營      |
| **訊息限制** | 1000 則/天            | 無限制           |
| **功能**     | 基本推送              | 按鈕、位置、圖片 |
| **成本**     | 免費                  | 免費             |

### Telegram 優勢

1. **持續可用**：LINE Notify 即將停止服務
2. **功能豐富**：互動按鈕、多圖傳送、位置分享
3. **無訊息限制**：每天數萬則訊息
4. **跨平台**：iOS、Android、Web、Desktop

## 為什麼需要深度過濾？

### 一般搜尋 vs 深度過濾

**一般搜尋**（591 基本篩選）：

```
地區：中山區
價格：≤ 12000
結果：200 筆（需人工逐一檢查）
```

**深度過濾**（自動化詳細條件）：

```
基本條件：地區 + 價格
必要條件：水泥隔間、硫化銅門、獨立電表、對外窗
加分條件：電梯、非一樓、浴室對外窗、變頻空調
結果：15 筆（高度符合）
```

### 符合度評分

- 必要條件：每項 25 分（總計 100 分）
- 加分條件：每項 10 分（總計 40 分）
- 門檻：≥100 分發送通知，≥120 分優先通知

**好處**：

1. 減少雜訊（200 筆 → 15 筆）
2. 優先級排序（高分房源優先）
3. 節省時間

## 技術權衡

### 即時性 vs 成本

**選擇**：每小時爬取一次

**理由**：

- 平衡即時性與成本
- 好房源通常數小時內有效
- 避免頻繁爬取觸發反爬蟲
- Vercel 免費方案足夠

### 準確性 vs 覆蓋率

**選擇**：高準確性優先

**理由**：

- 寧可錯過 1 個好房源，也不要看 10 個不符合的
- 符合度評分系統（100 分門檻）
- 必要條件全滿足才通知

---

## 結論

技術選型基於：

1. **實用性**：解決真實痛點（節省時間、提升效率）
2. **可行性**：技術成熟、可快速實現
3. **經濟性**：最小化成本（重用現有基礎設施）
4. **安全性**：避免帳號被封、資料洩露

在功能、成本、風險之間取得良好平衡。
