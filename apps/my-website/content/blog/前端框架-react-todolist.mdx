這是因為 React 會希望你幫每一個 component 加上一個唯一 id 這樣才方便辨別資料，所以 `.map()` 的部份需要另外加上一個 key


因為要用這個 id 幫助 React 去辨別說在更新 list 是刪除哪個元素，或是換位置，這只是為了要增加效率而已。

## 加上 localStorage

這是一種把資料處存在瀏覽器上面的方法。

這邊就要利用之前教的 lifecycle method，componentDidUpdate，因為是當資料跟原先的不同的時候，就可以通過這個方法來比較。

```
app.js App component:
  componentDidUpdate(prevProps, prevState) {
    if(prevState.todos !== this.state.todos) {
      window.localStorage.setItem('todoapp',
        JSON.stringify(this.state.todos));
    }
  }
```

因為 prevProps 跟 prevState 都是指狀態改變前一筆的狀態，所以就可以拿來跟已經新增完成的狀態做比較，有不同，就把資料儲存進去。

透過這樣就可以把資料儲存了。

取出來的話，則是要放在初始化的地方，也就是 componentDidMount，這邊就比較複雜一些了，要先拿出資料，然後在調整一下結構才可以放入 state

```
  componentDidMount() {
    const todoData = window.localStorage.getItem('todoapp');
    if (todoData) {
      const oldTodos = JSON.parse(todoData);
      this.setState({
        todos: oldTodos,
      })
      this.id = oldTodos[oldTodos.length - 1].id + 1
      // 當初設定就是只有最後一個 id 用來設定而已，
      // 所以這樣寫就可以得到最後一個 id 是多少
    }
  }
```

## 結論：

todolist 的部份，改用 React 之後，整體使用上來就更方便了。主要變成只需要管理資料而已了，不需要再去管畫面怎麼處理了。

一切的一切就只要把資料弄好之後，剩下就交給 React 即可。

透過 todolist 的例子，我們也可以分出來 Mounting 的時候到底是可以用來做什麼處理的，像是可以取得資料使用這樣子。

這部份跟我之前再做 todolist 的想法相同，本來是因為練習，所以大量使用 AJAX。但當作業做完之後，我就思考，應該可以把資料抓下來之後在 localStorage 儲存，然後資料的處理只需要處理 localStorage 跟 AJAX 等待 callback 確認有無成功即可。

就是因為當時我想說都寫了後端，就通通使用後端來傳資料，一方面當作練習大量練習使用 AJAX，所以該 todolist 可以說就是大量利用 AJAX 送資料跟取得資料。

這點在 React 上面就可以使用 Mounting 來處理這塊的部份，這真的是十分好的方式，也很契合我當時的想法。

而 Updating 的部份，則是平常變動的時候要如何處理資料的部份，在這邊的例子就是用來儲存資料，之後就是用來 AJAX 傳送資料跟確認而已了。也是一個很好用的部份。

總言之，透過 React 對於 render 機制的部份跟 render 的 lifecycle method 就可以協助我們很好的處理跟運用這些資料。

我會先運用三個部份來記憶該如何處理，Mounting、Updating、Unmounting。Mounting 用來處理初始化，Updating 就是使用者操作的部份，Unmounting 就是使用則移除資料的部份。不過 todolist 沒說到 Unmounting 的運用方式，所以這部份可能還要在多看看更多的例子才可以。
