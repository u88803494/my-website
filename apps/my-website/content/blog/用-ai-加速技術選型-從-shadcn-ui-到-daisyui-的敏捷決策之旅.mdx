在軟體開發中，「技術選型」往往決定了專案的成敗與開發效率。這個過程充滿了權衡與取捨。過去，這需要耗費大量時間研究。但在 AI 協作的時代，我們可以將其轉變為一場高效的技術對談，不僅找到答案，更釐清了答案背後的所有可能性。

本文將完整還原我最近在個人網站專案中，如何與我的 AI 助理（Gemini）協作，完成前端 UI 元件庫選型的真實經歷。這趟旅程從一個開放性問題開始，歷經了對 `shadcn/ui` 的專業嚮往、對 `daisyUI + Headless UI` 組合技的深度探索，最終才基於敏捷思維，做出了最務實的選擇。

### 起點：「我想做個網站，你推薦什麼？」

一切始於一個簡單的需求。為了打造一個專業的個人網站，我向 AI 尋求建議。考量到我對程式碼品質的追求，AI 的首選推薦是 `shadcn/ui`——一個讓開發者「擁有程式碼」、給予 100% 掌控權的元件庫。這完美契合我對專業的想像。

### 轉捩點：當「完美」遇上「速度」

然而，在深入討論後，我意識到我的首要目標是**「快速」**打造一個最小可行性產品 (MVP)。`shadcn/ui` 雖然完美，但其需要投入的組裝與設定時間，與我的當務之急有所衝突。

於是我立刻調整了問題：「我的核心需求是『快速』與『可用』，你會怎麼推薦？」

AI 迅速理解了我的優先級變化，並提出了截然不同的方案：**daisyUI**。它是一個基於 Tailwind CSS 的外掛，主打極速開發與豐富主題，能讓我像拼樂高一樣快速搭建頁面。

### 深度探索：「我能兩者兼得嗎？」

正當我準備接受這個「快速方案」時，一個工程師的慣性思維油然而生：「有沒有辦法，既要 daisyUI 的速度與外觀，又要 shadcn/ui 那樣穩固的底層邏輯？」

我向 AI 拋出了這個更具挑戰性的問題，於是，我們進入了本次討論最精華的部分 — — 探索 `daisyUI + Headless UI` 的組合技。

- **Headless UI**：由 Tailwind CSS 官方團隊成員開發，專門提供元件的「行為、狀態、與無障礙設計」（也就是「大腦」）。
- **daisyUI**：提供元件的「外觀樣式」（也就是「衣服」）。

這個組合的目標是「強強聯手」，用 Headless UI 解決互動邏輯，再用 daisyUI 快速美化外觀。AI 甚至為我展示了程式碼範例，說明如何將兩者結合。

![](https://cdn-images-1.medium.com/max/800/1*2hd8bYd3fK_NG4FQFUg0dA.png)

### 最終決策：擁抱敏捷，回歸初衷

`daisyUI + Headless UI` 的方案無疑是強大的，它幾乎是「魚與熊掌兼得」的完美解法。然而，它也帶來了新的權衡：**整合的複雜性**。我需要花費額外的心力去閱讀兩個函式庫的文件，並思考如何將它們完美地對應起來。

此時，AI 也點出了一個關鍵事實：`shadcn/ui` 本質上就是一個由專家幫你整合好的、高品質的「邏輯 (Radix UI) + 樣式 (Tailwind CSS)」方案，並且還把原始碼交給了你。

經過這番深度探索，我的思路變得前所未有的清晰。我意識到，為了追求「組合技」的完美，我將再次偏離「快速」這個核心目標。

因此，我做出了最終的、也是最明智的決定：**在 1.0 版本中，採用純粹的**`daisyUI`。

我選擇了「速度」，並坦然接受它在未來客製化深度上的限制。這是一個完全符合敏捷開發精神的決策 — — 用最小的成本，去實現當下最重要的目標，並將優化的可能性留給未來。

### 結論：AI 是你的思維放大器

這次的技術選型，如果沒有 AI，我可能在比較完 `shadcn/ui` 和 `daisyUI` 後就草草做出了決定。但透過與 AI 的深度對話，我得以：

1. **探索邊界**：不僅找到了 A 和 B，還挖掘出結合 A 和 B 的 C 方案。
2. **釐清權衡**：清晰地看到了每個方案背後的優點、缺點與隱性成本。
3. **強化決策**：我的最終選擇，不再是「二選一」的妥協，而是在看清了所有可能性之後，做出的充滿信心的戰略決策。

這就是 AI 協作的真正力量，它不是一個單純的「問答機器」，而是一個能陪你進行深度思辨、放大你思考層次的強大夥伴。
