## 入職第二個月：前端官網

當我做完以上的練習之後，就進入前端的部份。

在我面試這家公司的時候，對方跟我說因為我學習的很多，所以我對他們來說算是有一些經驗了。

老實說，當初面試得很辛苦，也辛苦很久，這句話給予我的認同感很大，但讓我意外的是說三個月的訓練期，卻很快得就讓我直接製作公司的官方網站。

當時公司網站本來是只有一個單一頁面，而這次是要我新增三個頁面，依照製作的順序分別是：

1. https://www.arisan.io/#/services
2. https://www.arisan.io/#/clio
3. https://www.arisan.io/#/faceta

當然囉，當時是沒有這些頁面的，這都是先展示已經完成的成品。

而公司的頁面原本是只用 JQuery 寫的，在這邊要改為 React 撰寫，所以也花了一些時間研究一下 React 的設定。

而先說一下這個網站實作最麻煩的部份在於，沒有使用 UI 套件，所以任何東西都要自己手刻，而這也是個風格強烈的網站，所以基本上，HTML 的原生要素是無法使用。這點會在後面製作表單的時候碰上。

這邊大致上也是學了不少，整體而言，大致上從 React 專案一開始的設置、規劃整體網站的架構、寫測試等。並且這是使用 Hook 來實作的產品，感覺還滿不錯的。

### 實作的難處

而接著很快就到了實作的部份，一開始其實沒這麼懂，所以我都是按照 JQuery 的型式在實作，從官網的內容可以看到，[網站](https://www.arisan.io/#/services)有大量斜角的規劃，而原本首頁的作法是用 SVG 切出一塊一塊的小三角、長方形以及矩形，然後拼在一起，變成整塊大三角，像下圖那樣。

![不要說這是不是做歪了，是本來就長這樣，要整體看才不會怪怪的](https://cdn-images-1.medium.com/max/800/1*dx4qONk7RQEQkZO9vEY_lw.png)

_不要說這是不是做歪了，是本來就長這樣，要整體看才不會怪怪的_

上方這一塊我就花了至少一天的時間在實作，因為他還需要往左右無線延伸下去，但無限這個字其實對網頁來說不太可能，所以後來才改為最大可支援到 4k 尺寸，這也是幾天後的事情了…

後來隨著進行，因為實作有點困難，有這麼多的大斜角，Service 頁面還有，其他的 CliO、Faceta 頁面一個比一個還長，難道都得這樣做，所以後來在與他人的討論中，才發現…，其實可以使用另外一種方式來實作。

### 實作網站背景

我公司的設計師還滿厲害的，雖然公司設計師目前是只負責設計，但目前的作法用到的 CSS 關鍵指令是她建議的。

在加上我後來思考一下，為什麼非得要把他們通通作在同一層，何不分開？就像我之前曾經實作過得五子棋那樣 — 分成棋盤層跟下棋層。

**這裡也可以分成背景層跟內容層。**

所以就有了目前的新版本的作法，直接把那些色塊做出來，放在背景層，然後使用翻轉的功能來方法`transform: skewY(7.9deg);` 來實作。

這下就簡單多了，每次頁面都只要看一下大概的色塊高度，然後再去翻轉需要的角度即可。

而這些，就作為背景層的內容使用，再把內容覆蓋上去。

### 串上網址以及捲動功能

前面都只有畫面，到這邊需要的是串上導向網址，然後捲動到需要的區塊以及製作表單。

在服務總覽頁面，是有實作一些按鈕功能。

![紅圈的功能是可以點擊的。](https://cdn-images-1.medium.com/max/800/1*PUMXNLdoWM4-4DvWQhf07A.png)

_紅圈的功能是可以點擊的。_

這些按鈕的功能，有的是可以彈出表單，有的是可以切換網頁並捲動到對應頁面。

可以試試這個網址：https://www.arisan.io/#/clio/device-health-monitoring

就會看到他切換到 CliO 頁面，然後捲動到這個網頁的一個特定區塊。

這是使用 [react-scroll](https://npmjs.com/package/react-scroll) 來實作的，然後還碰到一些問題，實際上一開始是沒辦法這麼好的捲動到需要的位置，甚至每次捲動都是到很接近就停了下來，思考後才想到，應該是網站沒 Render 完成我就直接捲動了才會失敗，最後就解了這個問題。

### 跨 component 傳值

所以在這邊就要使用到跨 component 傳 state 的功能，幸好 React hooks 很強大，所以這裡就很直接的使用 `useContext` 來實作，真心覺得比 Redux 方便好多，這也是我首次使用這個功能。

### 真正的挑戰，表單內容

就如同一開始說的，這表單難就難在，因為只能用純 CSS 來撰寫，因為網站風格強烈，所以 HTML 的原生元件都不能用，幾乎都要自己刻，當然也可能是我不夠厲害啦。不過即便如此，我還是盡量都使用應該搭配的標籤，而不是每個都是 div 到底。也為此我使用 stackoverflow 的機會大增，因為要一直去查詢如何改變原生 Html 標籤顯示的樣式。

像是選項的部份，就沒辦法使用原生的，因為跟設計稿的差異過大，也因此我學到的如何使用 div 搭配 `:before` 、 `:after` 來實作在內容前擺東西，像在這邊就是利用`:before` 、 `:after` 分別實作空選項的框框以及選中的樣式，然後控制他們交疊在一起，就變成看起來變成選項的樣式。

表單部份也是，變成純粹使用 div 來控制，為此我還去研究各大 UI library 是如何使用表單的。

### 另外一個挑戰：寫測試以及自動化佈署（CI/CD）

這邊就不著墨太多了，會算是挑戰是因為之前沒做過。不過基本上就是用 Jest 搭配 [puppeteer](https://npmjs.com/package/puppeteer) 來控制瀏覽器開啟之後拍照，作為之後改 code 的之後畫面會不會不同，然後這裡也學到，原來 chrome 在 linux 上跟 mac 是不一樣的，所以就需要在公司的伺服器拍好照之後，再把照片拿下來放到資料夾內，以便之後自動化佈署的時候做測試。而自動化佈署則是一堆一堆指令，對於有程式經驗來說不難，難點就是在運作的時候，會出現問題，必須慢慢調校才可以，以通過自動化佈署。

### 小結

也算是學了不少東西，事後想了想，雖然不能用 UI library，不過這樣也很好，因為我可以學到這些元件要如何自己手刻出來，是加強自己的基本功的好方法。在這之中，也研究了很多沒看過得東西，才可以實作出公司要求的東西。然後我覺得最重要的是學習要如何跟設計師溝通，才能做出公司要的東西。

## 入職 2.5 個月：提早脫離訓練期

我是 06/15 入職的，本來訓練期是三個月，應該是 9/15。而老闆說讓我在 9 月就正式脫離訓練期，也就是說提早半個月。雖然提早脫離，讓我有認同感，非常得高興，但也意味著要開始接觸公司的產品了。

### 正式投入產品：解 bug

我想一開始都是這樣吧，第一次解公司產品的問題，是給我一個解 CORS 問題的 bug，有很詳細的說明，如何做很快就知道了。

這裡的問題主要是後端使用轉址的方式請求資源，所以要改成從另外一個伺服器取得之後再把資料轉給前端即可。

而因為我很快就弄好了，所以下一個也是解 Bug，但是這次同事就不幫我看了。而這次的是跟播放器有關的 Bug 要我解，所以也是我要開始練習如何找問題點，然後寫出 issue 了。這次就比較吃力了，花了很多時間在看，然後才找出問題點。

### 正式投入產品：開發新分頁

接著很快不到半個月就開始要寫產品功能，這次是我寫公司產品的使用者界面。於是我花了一堆時間在研究之前程式的結構，然後用對應的方式去實作。而因為公司都是使用 Classical component，所以我就回到了之前的記憶，開始跟 life cycle 奮鬥XD

## 總結：各種方面的轉變

### 身體

為什麼要提這個，因為是轉職的最大一個因素之一。不用在輪班之後，即使每天開車上下班，我每天都感覺自己精神很好，也快樂很多。所以真心不推薦要輪班的工作。當然之後找到了房子之後，就更好了，每天也多了很多閒暇時間可以研究自己想研究的東西。

### 英文

公司的要求是幾乎都要用到英文，所以自己的英文寫作能力我相信應該是增加不少，然後用多了之後單字量也稍微變多一些。但真正的英文要好還有一段距離XD

### 溝通

在這之中，多練習了很多的溝通，跟設計師溝通、溝通需求、溝通自己的問題點等，在我前份公司大家都是不溝通的或是說難以溝通，所以這點對我來說差非常多，也是我自己需要逐步加強的部份。

### 寫作

為什麼會特別提這個？主要是因為跟溝通也有關係，而我之前在別篇文章也有提過，我是開始接觸 coding 之後才有辦法大量寫出文章，所以而在公司做寫 issue、merge request 都是需要寫作能力的，雖說是英文為主，但一開始英文不強，一定事先想想中文才轉成英文，只是會有文法差異而已。

### 最後

雖然這是一篇遲來的三個月心得（目前已經七個月了，哈…），但我還是盡量依照當時的情況來想想，所以是盡力不寫超過太多的心得，而當時的心境，事後看看 GitLab 上的 issues，還是可以回想得到當時的心路歷程，所以也算為了這篇下個完美的結尾了吧。

之前是有想要寫的六個月的心得，不過現在已經七個月了，嘆。而我依然會想寫一個心得，因為心境已經跟入職三個月的心情不太一樣了，思維也不一樣了，溝通能力也提昇了。
